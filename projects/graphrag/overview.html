GraphRAG + Vector Search: фармакологічна база знань

ІНДЗ № 3 — програмна реалізація та експериментальне дослідження (2026)

Цей навчальний проєкт порівнює три способи пошуку інформації в інструкціях до лікарських засобів: Vector-only, Graph-only та Hybrid (GraphRAG + Vector Search). Оцінюється пошук релевантних Drug ID, а не генерування текстової відповіді чи клінічні рекомендації.

1. Що реалізовано

Компонент Реалізація
Джерело даних openFDA Drug Labeling (SPL), зафіксований знімок 16.10.2026
Документи 25 справжніх інструкцій
Обробка 167 розділів; 1 072 текстові фрагменти по 150 слів, перекриття 30
Граф Neo4j 5.26 Community; у кінцевому збагаченому стані — 1 368 вузлів і 1 385 зв'язків
Вектори Qdrant 1.15.5; колекція pharma_chunks_bge_small_v1, 1 072 точки, розмірність 384, Cosine, HNSW
Модель BAAI/bge-small-en-v1.5 (FastEmbed)
Тестові запити 30 перевірених: 8 семантичних, 7 структурних, 10 із жорсткими умовами, 5 багатокрокових
Повторення 3 (19.10.2026) та 10 (20.10.2026)
Метрики Precision@1/3/5, Recall@1/3/5, FP, backend latency, embedding latency, CPU/RAM

Примітка до графа: експортований data/processed/edges.jsonl містить 1 384 зв'язки; ще один RESOLVES_TO_DRUG створюється під час scripts/07_enrich_interactions.py --apply, тому в робочій Neo4j було 1 385 зв'язків. Це послідовні стани того самого графа.

Важливо: наведені числа описують уже проведене дослідження. Для їх повторення з нуля потрібні той самий зафіксований корпус, перевірені анотації та еталонні відповіді. Повторне завантаження «живих» даних openFDA може дати інші документи.

Алгоритми

  • Vector-only: вектор запиту → пошук близьких текстових фрагментів у Qdrant → групування за унікальними Drug ID.
  • Graph-only: Cypher у Neo4j за явно заданими структурованими обмеженнями → унікальні Drug ID. Не застосовується до восьми суто семантичних запитів.
  • Hybrid: спочатку Neo4j визначає допустимі Drug ID, потім Qdrant ранжує текстові фрагменти лише всередині цієї множини. Для Q01–Q08 використовується Vector-only fallback.

Графові обмеження вже задано в метаданих тестового набору; автоматичне вилучення таких обмежень із природної мови не досліджувалося.

2. Склад проєкту

pharma_graphrag_pilot/
├─ README.md
├─ requirements.txt
├─ docker-compose.yml
├─ .env.example           # зразок без паролів
├─ .env                   # локальний пароль; НЕ передавати
├─ seeds.txt
├─ scripts/               # 01–18: отримання даних, підготовка, пошук, оцінювання
├─ schema/                # схема Neo4j
├─ annotations/           # перевірені твердження та семантика взаємодій
├─ benchmark/             # запити, gold та результати CSV/JSON
├─ data/raw/              # вихідний JSON openFDA
├─ data/processed/        # вузли, ребра, текстові фрагменти
├─ tests/
└─ docs/

Цей програмний архів містить повний локальний корпус data/raw/openfda_pilot.json, підготовлені фрагменти, перевірені анотації та gold-набір бенчмарку. Окремий архів GraphRAG_openFDA_dataset_25labels_1072chunks.zip можна подавати додатково як зручну форму датасету. Docker-томи зі станом баз до архіву не входять: на іншому комп’ютері бази потрібно побудувати за розділом 6.

3. Середовище

  • Windows 10/11, Python 3.10+ (py --version) і PowerShell для скриптів 01–17.
  • WSL2 Ubuntu + Docker Engine + Docker Compose plugin для Neo4j і Qdrant. На дослідницькому ноутбуці використовується саме цей спосіб, не Docker Desktop.
  • Доступ до Інтернету під час першого встановлення бібліотек, завантаження моделі та, за потреби, отримання даних із openFDA.

Windows PowerShell — установити залежності

Відкрити PowerShell у кореневій папці проєкту:

py --version
py -m pip install -r requirements.txt
py -m unittest discover -s tests -v

Файл .env

Якщо .env уже існує, не перезаписуйте його. Інакше скопіюйте .env.example до .env і задайте власний пароль Neo4j. Не додавайте .env до ZIP для викладача або публічного репозиторію.

Copy-Item .env.example .env

Для 03_import_neo4j.py потрібно окремо встановити той самий пароль у змінній середовища поточного сеансу PowerShell:

$env:NEO4J_PASSWORD = Read-Host "Введіть пароль Neo4j"

Не копіюйте пароль у звіт чи листування.

4. Запуск баз даних у WSL Ubuntu

Відкрити Ubuntu, перейти у папку проєкту на диску E (на інших ПК шлях може відрізнятися):

cd "/mnt/e/5 курс/бази даних/pharma_graphrag_pilot"
sudo docker compose up -d
sudo docker compose ps

Очікувані сервіси: neo4j та qdrant, стан Up.

  • Neo4j Browser: http://localhost:7474 (логін neo4j, пароль зі свого .env).
  • Qdrant Dashboard: http://localhost:6333/dashboard.

Після роботи зупинити в Ubuntu:

sudo docker compose stop

При повторному відкритті — знову sudo docker compose up -d. Не виконуйте docker compose down -v: ця команда видалить томи з даними баз.

5. Повторення вже підготовленого бенчмарку

Цей шлях призначений для існуючого, уже збагаченого проєкту. Потрібні:

  1. Робочі Neo4j і Qdrant із правильними даними (25 Drug, 1 072 TextChunk, 9 INTERACTS_WITH).
  2. data/processed/chunks.jsonl та інші файли підготовленого корпусу.
  3. benchmark/gold_review_working.csv з усіма 30 схваленими запитами та їхніми структурованими фільтрами.
  4. Локальний .env з паролем Neo4j.

Після запуску Docker у Windows PowerShell, у папці проєкту:

py scripts/17_benchmark_retrieval.py --preflight
py scripts/17_benchmark_retrieval.py --run --repeats 10

Спочатку має пройти --preflight без розбіжностей. Скрипт сам створить benchmark/run_YYYYMMDDTHHMMSSZ/ з:

  • retrieval_results.csv — докладні результати кожного запуску;
  • summary_by_category.csv — агреговані метрики за категоріями, режимами та k;
  • run_manifest.json — параметри запуску та методологічні обмеження.

Еталонні відповіді використовуються лише для оцінювання, а не для підбору кандидатів під час пошуку.

Окреме вимірювання серверних CPU/RAM

В Ubuntu, паралельно з Windows PowerShell:

sudo python3 scripts/18_monitor_docker_resources.py

Після BASELINE COMPLETE запустити бенчмарк у PowerShell. Після завершення натиснути Ctrl+C в Ubuntu. У benchmark/ з'являться docker_resources_...csv та docker_resources_..._summary.json. Ці вимірювання описують контейнери, а не Python-клієнт. Фаза load може містити час очікування до/після запуску тесту.

Демонстрація роботи трьох режимів (не бенчмарк)

py scripts/05_retrieval_modes.py

05_retrieval_modes.py — окремий приклад на конкретному препараті з явно переданими графовими умовами; його вихід не є метриками 30-запитного бенчмарку.

6. Побудова з зафіксованого корпусу (за потреби)

Не запускайте повторну індексацію на робочих даних без резервної копії: це окрема операція від повторення готового бенчмарку.

  1. У цьому програмному ZIP data/raw/openfda_pilot.json уже містить потрібний зафіксований знімок. Його не потрібно завантажувати повторно. Якщо дані відсутні, можна відновити їх із GraphRAG_openFDA_dataset_25labels_1072chunks.zip (dataset/openfda_labels_snapshot_25.json → data/raw/openfda_pilot.json).
  2. Мати annotations/verified_constraints.csv з попередньо перевіреними твердженнями. Для початкового, незбагаченого графа анотацій може не бути, проте це не дасть фінального benchmark-ready графа.
  3. Файли data/processed/ вже містяться у програмному архіві, тому для найшвидшого відтворення робочої бази можна одразу виконувати крок 4. Щоб додатково перевірити повторну підготовку корпусу, у PowerShell виконати:
py scripts/02_prepare_dataset.py --chunk-size 150 --overlap 30

У цьому переданому проєкті вже є annotations/verified_constraints.csv із 20 перевіреними фактами. Тому команда з параметрами за замовчуванням створює 25 інструкцій, 1 072 фрагменти, 1 368 вузлів і 1 384 зв'язки у файлах data/processed/. Статистика 1 349 вузлів і 1 364 зв'язки описує попередній базовий етап без ручних анотацій, а не результат цього запуску. Після імпорту та 07_enrich_interactions.py --apply у робочому Neo4j буде 1 385 зв'язків.

  1. Імпортувати в Neo4j (після встановлення NEO4J_PASSWORD) і побудувати колекцію Qdrant:
py scripts/03_import_neo4j.py
py scripts/04_index_qdrant.py
  1. Для відтворення збагаченого графа потрібні факти у annotations/verified_constraints.csv та annotations/interaction_semantics_9.csv і відповідні операції збагачення:
py scripts/07_enrich_interactions.py --check-csv
py scripts/07_enrich_interactions.py --check
py scripts/07_enrich_interactions.py --apply

--apply змінює Neo4j після підтвердження. Виконуйте ці команди лише за наявності перевірених вихідних файлів і правильної бази. Не підмінюйте відсутні анотації автоматичними припущеннями.

  1. Для бенчмарку також потрібен перевірений benchmark/gold_review_working.csv. Скрипти 08–16 документують підготовку й ручне уточнення цих еталонів; відтворення точно такого самого gold вимагає збереженого CSV з дослідження.

Альтернативно 01_fetch_openfda.py може зробити новий запит до API, але такий корпус не варто називати тим самим зафіксованим експериментом:

py scripts/01_fetch_openfda.py --max-labels 25 --per-drug 50

7. Основні результати дослідження

На 22 структурованих запитах (головний запуск: 10 повторень, k=3):

Показник Vector-only Graph-only Hybrid
Precision@3 34,85% 42,42% 42,42%
Recall@3 81,82% 100,00% 100,00%
Частка FP серед повернутих 65,15% 0,00% 0,00%
Середній час backend 14,63 мс 7,33 мс 31,89 мс

Graph-only і Hybrid часто повертають менше ніж три правильні препарати, тому Precision@3 обчислюється з фіксованим знаменником 3; відсутність FP не означає Precision@3 = 100%.

Моніторинг контейнерів: Neo4j — CPU baseline/load* 2,34/6,89%, RAM 740,7/750,7 MiB; Qdrant — 0,38/2,43%, RAM 63,9/65,7 MiB. load* включає частину очікування між командами. Результати стосуються невеликого, спеціально підготовленого корпусу й не доводять придатність системи для клінічного застосування.

8. Що передавати викладачеві

  • Звіт GraphRAG_INDZ_final_report.docx (окремо від програмного архіву).
  • Код: scripts/, schema/, tests/, README.md, requirements.txt, docker-compose.yml, .env.example, seeds.txt.
  • Дані: зафіксований корпус openFDA; файли data/processed/ для точного повторення індексації; перевірені CSV в annotations/.
  • Результати: benchmark/gold_review_working.csv, benchmark/run_20261020T072843Z/ та benchmark/docker_resources_20261020T072704Z*.

Ніколи не вкладати: .env з паролем, реальні токени API, локальні .venv, тимчасові кеші. Дані openFDA зберігати із зазначенням джерела та дати знімка.

9. Джерела та обмеження

  • openFDA Drug Label API: https://open.fda.gov/apis/drug/label/
  • Neo4j: https://neo4j.com/docs/
  • Qdrant: https://qdrant.tech/documentation/
  • FastEmbed: https://github.com/qdrant/fastembed

Це навчальний прототип retrieval, а не медичний довідник або засіб вибору лікування. Відсутність відношення в графі не підтверджує безпечність препарату. Еталонні відповіді формувалися в межах цього корпусу; результати не є незалежним зовнішнім клінічним тестуванням.
